# R13 · 国际化与多库 locale 同步

## 学习目标

- 用 Vue I18n Composition API 管理中英文消息
- 让 Vue I18n、Naive UI 与 dayjs 的 locale 在同一个 app-store 状态上同步
- 让菜单、面包屑、页签和页面文案在切换语言时一起更新
- 使当前 locale 持久化，冷启动时不闪回默认语言

## 对照 legacy

- `legacy/src/locales/index.ts`
- `legacy/src/locales/langs/zh-cn.ts`
- `legacy/src/locales/langs/en-us.ts`
- `legacy/src/locales/naive.ts`
- `legacy/src/locales/dayjs.ts`
- `legacy/src/components/common/lang-switch.vue`
- `legacy/src/store/modules/app/index.ts`

## 动手步骤

### 1. 安装依赖

```bash
bun add vue-i18n dayjs
# R11 未安装 naive-ui 时再补：
bun add naive-ui
```

### 2. 建立消息目录

```text
src/locales/
  index.ts
  langs/zh-cn.ts
  langs/en-us.ts
  naive.ts
  dayjs.ts
```

主线先翻译：登录、登出、首页菜单、面包屑、tab label、403/404/500 标题与常用按钮。

### 3. 创建 Composition API 模式的 i18n

```ts
createI18n({
  legacy: false,
  locale: 'zh-CN',
  fallbackLocale: 'en-US',
  messages: { 'zh-CN': zhCN, 'en-US': enUS }
});
```

在 `main.ts` 按 store → router → i18n → mount 的顺序注册。

### 4. 以 app-store locale 为唯一状态源

locale 变化时同步：

- `i18n.global.locale.value`；
- `NConfigProvider` 的 `locale` 与 `date-locale`；
- `dayjs.locale(...)`；
- `document.documentElement.lang`。

不要在语言按钮里分别修改四处。按钮只调 store action。

### 5. 让路由投影保持响应式

R11/R12 的菜单、面包屑和 tab 优先保存 `i18nKey`，渲染时再 `t(key)`。如已保存 label，切换 locale 时必须可重算，不允许混合出现中英文旧值。

### 6. 持久化与首屏

在创建 i18n / mount 之前先从 storage 读取 locale。对无效 locale 回退到明确默认值，不盲信 storage 字符串。

## 常见坑

- **只切 Vue I18n**：Naive UI 与 dayjs 仍是原语言。
- **菜单 store 存已翻译 label**：切换语言后旧 label 不重算。
- **启动后才读 storage**：首屏闪烁错误语言。
- **中英消息树结构不同**：回退隐藏了缺失键，到验收才发现漏翻。

## 思考题

1. 为什么路由 meta 存 `i18nKey` 比存翻译后 label 更稳？
2. locale 是 app 状态还是 theme 状态？这个归类对依赖方向有什么影响？

## 不要做

- 不要一次搬入 legacy 的所有翻译键
- 不要将 locale 切换分散到多个组件
- 不要在本轮同时实现完整主题设置，R14 单独处理
